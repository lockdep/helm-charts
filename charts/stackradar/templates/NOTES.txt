{{- if .Values.scanner.enabled }}

The scanner starts beside the server and reports as cluster `local`. The
server creates that cluster and its key at start-up from the bootstrap
credential, so the scanner's first heartbeats may be rejected for a few
seconds and then accepted — that is expected. This cluster's own images show
up with findings once the first pod sweep and the OSV bootstrap are done
(minutes for the default ecosystem list, depending on your connection; the
UI says so until then).
{{- end }}

Migrations: every server and client pod applies its own chain at start-up
under a Postgres advisory lock{{ if .Values.initializer.enabled }} — except here: initializer.enabled moved

If a pod stays NotReady for an unusually long time, read its logs:

  kubectl --namespace {{ .Release.Namespace }} logs deploy/{{ $serverSvc }}
  kubectl --namespace {{ .Release.Namespace }} logs deploy/{{ $clientSvc }}

`/api/health/ready` on either names the problem rather than the value.

{{- if .Values.postgresql.enabled }}

The bundled Postgres is one node, no HA, no automated backups and no managed
major upgrades. Its volume is retained by `helm uninstall`. Back it up with:

  kubectl --namespace {{ .Release.Namespace }} exec {{ include "stackradar.postgresql.fullname" . }}-0 -- \
    pg_dump -U {{ .Values.postgresql.auth.username }} -Fc {{ .Values.postgresql.auth.database }} > stackradar.dump

When it stops being enough, "Moving to your own Postgres" in the chart
README is the way out.
{{- end }}
